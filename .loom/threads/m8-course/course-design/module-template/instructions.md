# Module template and notation conventions

Write `docs/module-template.md` and one worked sample section.

- Fixed sections for every module: outcomes, prerequisites, reading (manual
  sections and pages), concepts, worked examples, lab, etude with its form
  plan, self-assessment rubric, extensions, summary.
- Notation: how phrase, chain, song and table grids appear on the page
  (monospace grid with the unit's column order, hex values), how instrument
  patches appear (parameter tables), how key presses are written, and how
  staff-notation ideas get translated into tracker rows.
- Voice: direct, second person, assumes music theory and programming
  literacy; defines tracker terms on first use.
- Hardware: assume a standard unit and the manual's key names. Where headless
  might differ, say so in a short, consistently styled note.
- Honesty rule: mark any parameter value that has not been tried on a unit as
  a starting point to adjust by ear.
